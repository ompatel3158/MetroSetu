# Offline-First Architecture Rules

These rules are MANDATORY for all development in this workspace to ensure 100% offline demonstration capability.

## 1. Zero External Network Calls at Runtime
- **No External CDNs**: Never reference external CDNs (e.g., `cdnjs`, `jsdelivr`, `unpkg`, `bootstrapcdn`, etc.) in HTML, CSS, or JS. All libraries (Chart.js, Leaflet, etc.) must be downloaded and bundled locally in `/static/js/` or `/static/css/`.
- **No External Fonts or Styles**: Never load external fonts (e.g., `fonts.googleapis.com`, `font-awesome`). Use the native system font stack:
  ```css
  font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
  ```
- **Inline SVGs**: Use inline SVGs or local SVG files for icons to avoid external icon font downloads.
- **No Remote AI/Cloud APIs**: Never call external AI APIs (OpenAI, Gemini API, Claude API, etc.) in runtime flows. All AI, NLP, prediction, and heuristics must run on-device locally in Python (or local offline models).

## 2. Strict Database Isolation (`db.py`)
- All database queries, schema definitions, connection management, and mutations MUST live exclusively in `db.py`.
- No other module (`main.py`, `ai_engine.py`, `seed.py`, etc.) may import `sqlite3` or execute raw SQL.
- Queries must return standard Python dicts/lists so that swapping the database backend requires changing only `db.py`.

## 3. Offline Resilience & Service Worker
- The frontend must register a Service Worker (`/sw.js`) served from root scope.
- Static assets (HTML, CSS, JS, images) must use a Cache-First / Pre-cache strategy.
- API endpoints (`/api/*`) must use a Network-First strategy with Cache Fallback so data viewed previously remains accessible when disconnected.
- The UI must always display a visible Online/Offline status indicator with periodic heartbeat pings to `/api/health`.
- Offline submissions must be saved to a local queue (`localStorage` or IndexedDB) with user notification, and automatically synced upon reconnection.

## 4. Realistic Local Datasets (`seed.py`)
- All demonstrations must run with rich, self-contained local sample data generated by `seed.py`.
- Data must accurately reflect the Gujarat Metro (Ahmedabad / Gandhinagar) transit environment.
